**L2 补上了 L1 看不到的一件事：同一个 L1 在两个助手层里是两种不同的东西。** “依赖前文的修改或追问”在助手头部占 44.353%、助手随机占 25.708%，看上去只是量的差别。拆到子意图就不是了：`CONTEXT_DEPENDENT_REVISION_OR_FOLLOWUP__3` 在助手头部 24.941%、助手随机只有 3.253%；`CONTEXT_DEPENDENT_REVISION_OR_FOLLOWUP__1` 反过来，助手头部 10.353%、助手随机 22.036%（matrix_td_l2.csv: 各快照_占比%）。靠代表串辨识：__3 是「少一点」「短一点」这类对长度与格式的改写要求，__1 是「那就来吧」「不要弄表格」这类承接性的对话残片。两者在助手头部与助手随机各占一头。

**极差最小的大子意图，但它不是“四个快照都平”。** `OBTAIN_READY_TO_POST_COPY__5` 是 4.165% / 3.132% / 5.294% / 5.352%，极差只有 2.22pp（matrix_td_l2.csv: 各快照_占比% / 极差pp）——全语料 500 行以上的 10 个子意图里它的极差最小，次小的是 4.662pp。但极差小不等于测不出差别：六个两两对比里有三个显著——年度 -1.033pp [-1.556, -0.514]、2026搜索 对 助手头部1k +2.163pp [0.8, 3.909]、2026搜索 对 助手随机1k +2.22pp [0.912, 3.869]；真正平的是 2025搜索 对两个助手层（+1.129pp [-0.247, 2.886] 与 +1.187pp [-0.137, 2.846]）和助手内部那一对（+0.057pp [-2.071, 2.141]）（newcombe_td_l2.csv: 差_pp / 低_pp / 高_pp / 显著）。

**细分让“缺席”变得容易，读的时候要折价。** L2 有 59 个类，仅搜索 9 个、真缺席条目 24 条；L1 只有 20 个类，仅搜索 0 个、真缺席条目 2 条（summary.json: levels）。把同样的行切得更细，每个格子的期望条数就更小，一个 850 行的快照抽到 0 条也更容易——这是切分粒度的结果，不是助手侧少了 9 种需求。
<!--/NARR:子层-->
<!--NARR:独有性-->
**先说结论：四个层级上，“仅助手”都是 0 个。** L1 仅搜索 0 个、L2 仅搜索 9 个、家族 1 个、叶 2 个，独占单个快照的类在四个层级上全是 0（summary.json: levels）。

**“0 个仅助手类”这句话在 L1 上是有把握的，在更细的层上不是。** 助手侧最小的 L1 类有 5 行，发生率 0.2773%；同样的发生率放到搜索侧 19,983 行上，期望 55.4 条，一条都不出现的概率 <0.0001（assistant_only_power.csv）。但在 L2、家族、叶三层，助手侧最小类只有 1 行、发生率 0.0555%，搜索侧期望只有 11.1 条——同一句话在那三层的把握小得多。

**反方向的检出力弱得多，而且这是结构性的。** 助手侧合计 n = 1,803，搜索侧 n = 19,983（interface_td_l1.csv: 搜索n / 助手n）。两边行数相差十一倍，所以“只出现在搜索里”远比“只出现在助手里”容易达成；读 6.1 节的“仅搜索”清单时必须先看这个不对称，不能读成“助手那边没有这种需求”。叶层两个仅搜索类确实过了检出力：漫画App官方下载入口查询（助手侧期望 31.04 条、P(0)=0）与 报刊电子版查询（期望 20.3 条、P(0)=0），判定都是真缺席（interface_bu_leaf.csv: 另一边期望条数 / 另一边P(0) / 缺席判定）。它们的可引例子是「联合早报」「人民日报」「新京报电子版」这类点名的报刊入口（examples_bu_leaf.csv）——一个要“到达某个站点”的需求，在助手导出里没有对应写法。

**不许写成发现的那几条。** “索取受限、欺骗性或有害内容”在 助手头部1k 是 0 条，但期望条数只有 4.51、P(0)=0.0109，判定是**偏少但证据弱**（absence_td_l1.csv: 期望条数 / P(0) / 判定）。同一张 L1 缺席表里只有两条够得上真缺席：查询官方政策法规或合规原文（期望 22.33、P(0)=0）与 查询具体数字或年度主题（期望 15.92、P(0)=0）。L2 层还有**不可判定**的条目，例如 `NAVIGATE_TO_SITE__1` 在助手头部期望 0.77 条、P(0)=0.4622——抽不到才是常态（absence_td_l2.csv）。

**最后是规则六，这里必须写出来。** 这套体系是把四个快照合成一份语料一次跑出来的，而这份语料 19,983 / 21,786 = 91.7% 是搜索行。所以“没有任何一个类只出现在助手里”是关于**交付分区**的陈述，不是关于需求本身的陈述：助手侧独有的写法完全可能已经被并进了一个以搜索行为主的类，或者落进了兜底类。本域有直接证据——助手随机层 60.756% 的行落在“生成角色扮演对话”一个叶里（matrix_bu_leaf.csv），而该叶的全语料置信度只有 0.5448（confidence_bu_leaf.csv）。一个吸走某一层六成行的低置信度叶，正是这种合并最可能发生的地方。
<!--/NARR:独有性-->
<!--NARR:路线交叉-->
**这一节问的是：同一个类，在不同快照里装的是不是同一批东西。** 意图体系自上而下写出、聚类树自下而上长出，两者独立，所以“这个意图在搜索里主要落在 A 叶、在助手里主要落在 B 叶”是一个测量。值得先看一个分布：43 个意图对比里超出同源噪声上界的有 27 个，其中只有 2 个是 2025搜索 对 2026搜索；53 个叶对比里超出的 25 个中，年度对只有 1 个（intent_leafmix.csv / leaf_intentmix.csv: 超出噪声）。**内部成分被换掉这件事几乎全部发生在跨界面与跨助手层，两年之间基本还是同一批东西。**

**最强的一条：一个叶在三个快照里有三个不同的主导意图。** “生成角色扮演对话”在 2025搜索 的主导意图是 查询词语或概念的含义（25.93%），在 助手头部1k 是 依赖前文的修改或追问（66.2%），在 助手随机1k 是 倾诉并寻求情绪支持（38.17%）（leaf_intentmix.csv: a主导内层 / b主导内层）——最后这个主导意图正是那个低置信度兜底类（置信度 0.5513，而它自己的主导叶就是“生成角色扮演对话”、占该类 85.0%），所以第三个快照上的“不同”有一部分只是这两个低置信度类互相指认。这三个快照两两之间的内层 TVD 是 0.6607、0.569、0.5059，对应的同源噪声上界只有 0.2878、0.2374、0.1998，三对全部超出。**这个叶名在三个快照里指的是三样东西**，任何按叶名做的跨快照汇总都会把它们加到一起。

**第二条：“调整生成结果”在搜索侧是残余，在助手侧才是它的字面意思。** 2025搜索 里这个叶的主导意图是 获取说明性/参考图片（26.03%），助手头部1k 里是 依赖前文的修改或追问（88.42%），内层 TVD 0.7457、噪声上界 0.1418（leaf_intentmix.csv）。可引例子对得上：搜索侧是「背景图」「简历」，助手头部是「少一点」「简单一点」（examples_bu_leaf.csv）。该叶在搜索侧只有 0.731% 与 0.59%，在助手头部是 33.529%（matrix_bu_leaf.csv），所以两年搜索里的那一百多行更像是被这个形态叶吸过去的残余。

**份额几乎没变、里面却换了东西的，全语料里只有这几处。** 逐条把内层 TVD 超噪声的条目和外层份额的 Newcombe 区间对照，只剩五条：
- “再生成与调整回答”助手头部 6.824% 对 助手随机 6.086%，差 -0.737pp、区间 [-3.065, 1.536] 含 0（newcombe_bu_leaf.csv），而内层意图分布 TVD 0.431 > 噪声 0.3276（leaf_intentmix.csv）。份额测不出差别，成分变了。**但两侧 n 都只有 58**，这一条只能当线索。
- “获取故事或典故全文/梗概”2025搜索 3.895% 对 2026搜索 4.222%，差 0.327pp、区间 [-0.22, 0.876] 含 0，内层叶分布 TVD 0.1007、噪声上界 0.0966（intent_leafmix.csv）。这是唯一一条落在大 n（389 与 422 行）上的年度“换血”，但余量只有千分之四，读作“可能在动”，不读作结论。
- 另外三条（获取说明性/参考图片、查询词语或概念的含义、生成或修改图片，都是 助手头部1k → 助手随机1k）**看起来像发现，其实多半不是**：三条的 b 侧主导叶全部变成了“生成角色扮演对话”，而这个叶本身就占 助手随机1k 的 60.756%。任何一个在该层只有几十行的意图，它的主导叶都有很大机会是这个叶。三条的 n 分别只有 42/61、32/40、47/35，**这是基线效应，不是逐意图的结果**。

**反过来，也有“份额变了、成分没变”的。** “获取现成可直接发布文案”在四个快照的主导叶都是“文案短句查询”，四个快照的集中度是 2025搜索 54.95%、2026搜索 58.21%、助手头部1k 73.41%、助手随机1k 74.64%（intent_leafmix.csv: a主导占比% / b主导占比%）。**四个数依次升高，但表里不给这四个数的区间，所以“一路升高”只能作方向性描述。** 表能判的是内层分布有没有超出同源噪声：搜索对助手的四对全部超出（内层TVD 0.2673 / 0.2922 / 0.2458 / 0.2595，同源噪声上界 0.1029 / 0.1462 / 0.1058 / 0.1434），而**两年之间那一级判不出**——内层TVD 0.0597 低于同源噪声上界 0.0695，超出噪声=否（intent_leafmix.csv: 内层TVD / 同源噪声上界 / 超出噪声）。所以站得住的是搜索与助手之间那一级，不是四点趋势。同一个意图，在助手侧被更彻底地收进同一个叶——可引例子也从搜索侧的「七月你好文案」「旅游文案短句干净治愈」，变成助手侧的「精简成适合朋友圈的短句」「精简成一句短吐槽文案」（examples_bu_leaf.csv）。这一条是本节唯一一条有噪声上界支撑的“份额没换、成分也没换、只是更集中”的现象，但支撑它的只有搜索对助手那一级。

**哪些格子的 n 太小，不能单独拿出来说。** 助手头部1k 只有 850 行、助手随机1k 只有 953 行。20 个 L1 意图里，有十个在 助手头部1k 只有 5 行或更少（matrix_td_l1.csv: 助手头部1k_条数，逐行清点）。这些格子的 Wilson 区间宽到没有分辨力：例如 获取可套用文书模板或范文 在该快照是 0.588%，区间 [0.252, 1.37]（matrix_td_l1.csv: 助手头部1k_95CI低%/高%）。凡是助手侧个位数条数的类，本表只能说“很少”，不能说“比搜索侧少多少”。

**哪些类的定义本身就含糊。** 置信度最低的五个 L1 全在 0.5 到 0.58 之间（confidence_td_l1.csv），叶层盲评一致性只有 2.0 的有三个（matrix_bu_leaf.csv）。歧义率也指向同一批：生成或修改图片 在 2025搜索 的聚类歧义率 66.67%（n=3）、现场生成或改写文字内容 在 2026搜索 是 23.75%（confidence_td_l1.csv: 聚类歧义%）。家族层有一个被判为不连贯（matrix_bu_family_final.csv: 家族内部一致）。**这些类的占比可以引用，但必须连着它们的置信度一起引用**，否则就是在把一个兜底类当成一块需求。

**哪些差异被时间与仪器混淆。** 两个搜索快照都抓在 7 月初，助手导出约在八月下旬。所以七一、七月你好、早安问候这类日历素材（七月及七一图片与祝福语查询 2.111%、早安问候图片查询 1.712%，matrix_bu_leaf.csv: 全语料占比%）在搜索侧是抓取日期的产物，它们在助手侧接近 0 不能归因于界面。助手侧的流量字段同样不可比：本域助手头部的高 PV 行大量是产品功能位而不是用户需求，所以本报告一律用行占比，表 L1-D 的流量加权列只能在同一快照内部读。**本域没有语音导出**，所以“输入方式”这条对比线整条不存在——不是测了没差别，是没有这条线（summary.json: snapshots 只有四个）。

**本报告的风险标注来自哪里，不来自哪里。** 表里的“体系内风险标注”是架构师写的，而 `risk_screen.json` 记的是运行当时的领域档案——四个类、1,096 行、占 5.03%（summary.json: risk_flagged_rows）。风控哨兵那 6 条发现**不在**那份文件里，所以本报告的风险占比不是一次完整筛查的结果，补充筛查要另做。引用护栏同理：71 个被运行点名过的字符串与整类不可引的性/危机类目一律只给条数与来源分布，可引行 20,016 / 21,786（summary.json）。

**两项分析这一批做不了，是略去，不是没发现。** 其一，`p5_taxonomy_delta` 需要一次同样行的纯搜索对照运行来逐行比标签，本域没有对应的 `book-pool` 运行，所以“加入助手行以后体系本身变了多少”在本域无法回答。其二，`p5_residue` 与 `p5_vs_unified` 需要 13 类通用框架标在同样的字符串上，本域实测覆盖率只有 0.5%（五域皆 100%），脚本带着覆盖率拒绝运行——在覆盖 0.5% 的框架上切残余类，每个格子都是噪声。最后重复一次全局前提：本次为 `mode=fast`，单标注员，**kappa 不存在，不是 1.0**，上面每一个占比都建立在一个没有第二意见校验的标注层上。
