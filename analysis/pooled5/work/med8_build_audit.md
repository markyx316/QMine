## 2. 与已交付的 `医疗_pooled5.parquet`（med-pool5）的关系

五个共有快照（2025搜索、2026搜索、助手头部、助手随机、助手语音1k）在 query / source / surface / l2 / tier / pv_raw / pv_norm 七列上**逐格相同**（构建时断言）。唯一的表示差异是缺失值：旧 parquet 把没有 `l2` 的格子存成字符串类型的 NaN，新构建是 pd.NA——两边都缺失、没有一格只在一边缺失、没有一格取值不同；断言按「两边都缺失即相等」写。
所以本语料是已交付语料的**严格超集**，结果差异只可能来自三份新导出与重新挖掘。

## 3. 语音头部的截断（本域与金融8 不同）

`医疗ai_voice_top1k.xlsx` 实为 **10,000** 行、按 `wise_pv` 降序（金融的同名导出是 1,000 行）。第 1,000 行的 PV 为 **11**，PV=11 的并列行有 **152** 行，分布在第 916–1,067 行。按导出顺序取前 1,000 行会只凭顺序收下其中一部分、拒掉另一部分，所以本快照取 **PV ≥ 11 的全部 1,067 行**（占该导出 PV 的 38.71%），其余 8,933 行不在设计内、不入挖掘。构建脚本断言导出按 PV 降序、且被排除的行 PV 严格更低。
