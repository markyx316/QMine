# 多垂类 AI 助手日志的挖掘方法

> English: [`AI_ASSISTANT_CORPUS.md`](AI_ASSISTANT_CORPUS.md)

两份 `ai助手` 导出如何被改造成流水线可以挖掘的语料，以及下一份导出到来时可以重复的
通用流程。本文每个数字都测自合并后的 65,986 行语料；没有一个是从此前五个单垂类语料
继承来的。

一句话概括：**有三个性质决定了后面所有的决策，而它们都无法从列名看出来。**

---

## 0. 这两份文件到底是什么

| | `ai助手_Top1000query.xlsx` | `ai助手_随机1000query.xlsx` |
|---|---|---|
| 行数 | 33,000 | 33,000 |
| 抽样设计 | 每个垂类按 `search_num` 取前 1,000 | 每个垂类随机取 1,000 |
| 类目 | 33 个一级、213 个二级 | 同上 |
| 总流量 | 30,428,147 | 42,414 |
| query 长度中位数 | 各垂类 3–12 字 | 10–23 字 |
| 两边相同的 query 串 | **159** 条，Jaccard 仅 0.2% | |

它们是**同一时间段的两个抽样分层**，不是两个时间点。这一条决定了 §2。

## 1. 先做画像，再动配置

四项测量，按此顺序。每一项都改变了一个配置决策。

**1.1 头部装的是 query 吗？** 按流量排序，读前 25 条。这里是：`总结全文概要`（580 万）、
`变清晰`（523 万）、`去水印`（178 万）、`👌 好的，继续吧`（213 万，横跨 32 个垂类）、
`嗯`、`需要`、`好`。这些是工具面板按钮、建议回复气泡和纯对话轮次 —— 不是被输入的意图。

**1.2 每个串横跨多少垂类？** 统计每个 query 串出现在多少个一级类目下。一个串出现在
33 个垂类中的 32 个，它就不是主题性的。

> **7 个串承载了合并头部流量的 15.97%，且各自出现在 33 个垂类中的 29–32 个。**
> 完整的「确认/继续」族是 1,065 行；在「各垂类等权」的口径下它占头部流量的
> **28.9%** —— 各垂类中位数 **30.1%**，生活和情感高达 **71.9%**。

**1.3 流量在垂类之间可比吗？** 取头部文件中每个垂类 `search_num` 的最小值，那就是它的
TopN 门槛。这里从 **3（招商加盟）到 419（书籍文档）**，所以这份文件是 **33 个在 33 个
不同深度截断的普查**的并集，原始流量在垂类之间不可比。按原始 PV，两个垂类就占了合并
权重的 55%，单个串占 17%。

**1.4 能不能还原到总体？** 要测，不要假设。捕获-再捕获桥接 —— 随机样本中有多大比例落在
头部门槛之上 —— 在这里**失败了**：33 个垂类中有 **17 个**在其门槛之上一条随机行都没有，
28 个不足 5 条，于是估计量会用 1 行推出 1,000,000 个去重 query。

> **这两份文件无法支持跨垂类的流量比较。** 如实说明，不要去估。这与
> `DRIFT_ANALYSIS.md` 中放弃幂律外推是同一条纪律。

## 2. 合并之前，先定「对比轴」

两个错误答案都很诱人。

**两份文件各跑一次**会彻底失去可比性。本项目自己的语料上测过：`fin01` 与 `fin02`
是同一垂类跑两次，得到 20 类和 19 类，**共享代码为 0** —— `LOOKUP_FX_RATE` 与
`FX_RATE_LOOKUP` 说的是同一件事，却无法对齐。两次运行给出的是两套词汇表。

**用 `--input head,tail` 传入**会正确地合并，然后**错误地描述**它们。那条路径会把行
标记为 `_snapshot` 并交付「快照对比 · 漂移分析」，而它的解释性句子是「不是趋势」、
「同月同日不等于季节可比」、「时段性事件」—— 对头尾分层来说没有一句是真的。其中一句
甚至**完全反了**：

> 「两期的抽样方式必须一致」警告的是：抽样口径不同会伪装成真实变化。但在按流量取的
> 头部与随机抽的尾部之间，**抽样口径的不同正是自变量**。读者套用这条告诫，会以为整份
> 文档被混杂了，而它恰恰在测它要测的东西。

**我们采用的第三条路：**合并成一个文件、带一列 `stratum`，并设
`data.comparison_axis: stratum`。`ops/drift.py` 本来就不知道时间的存在 —— 它比较的是
两个分组的构成 —— 所以只有措辞会变。运行交付 `分层对比_头尾结构差异.md`。`time` 分支
保持不变，已按七种 payload 形态逐字节对齐。

## 3. 构建语料

```bash
python tools/prepare_assistant_corpus.py \
    --head ~/Downloads/ai助手_Top1000query.xlsx \
    --tail ~/Downloads/ai助手_随机1000query.xlsx \
    -o data/raw/ai_assistant_pooled.parquet --show-ack
```

四个决策，理由都写在该工具的 docstring 里：

| 决策 | 为什么 |
|---|---|
| 合并，不要跑两次 | §2 —— 必须由同一套类目体系给两边打标 |
| 去重**只在 (stratum, l1, l2) 内做** | 类目本身是数据；跨类目合并会把 `👌 好的，继续吧` 的 213 万 PV 全部塞进众数类目。实际合并了 13 行完全重复的行，跨类目出现保留为独立行并带 `n_l1_categories` 列 |
| 权重用 `pv_norm`，不用 `search_num` | §1.3。在 (stratum, 垂类) 内归一到 1,000，于是流量占比读作「一个典型垂类在该层内的流量份额」。`search_num` 仍保留在文件里 |
| 分层标签用 `top1k` / `random1k`，不用 `head` / `tail` | `tail` 是关于这些行落在流量分布哪一段的**结论**；这份文件是**随机抽样**，那是关于它怎么抽的陈述。实测随机层只有 0.35% 落在 top-1000 门槛之上 —— 两层确实近乎不重叠，但那是测量结果而非抽样保证，而拿到 `tail` 这个名字的读者分不清自己得到的是哪一种断言 |
| 「确认/继续」行只**标记**、绝不删除 | 它们占头部流量约 29% 本身就是这份语料最大的发现，而被删掉的行无法被报告。`is_ack` 使用一条写明、可审计的模式，两端都锚定，因此 `好的` 命中而 `好的，帮我写一份年终总结` 不命中 |

## 4. 领域画像的种子来自测量

`configs/domains/ai_assistant_zh.yaml`。`TemplateSeed` 的契约是*凡匹配此正则的几乎
一定是同一意图* —— 这是一个关于数据的断言，所以要拿数据去检验：

```bash
python tools/check_domain_profile.py configs/domains/ai_assistant_zh.yaml \
    data/raw/ai_assistant_pooled.parquet --text-column query --weight pv_norm
```

**重要的是重叠率，不是覆盖率。** 12 条种子的重叠率都 ≤3.8%，其中 8 条为 0。有两个候选
因为过不了这一关被砍掉 —— 早期的 `roleplay` 与 `write_compose` 重叠 18.9%，被收窄为
`roleplay_persona`。

有三条种子只匹配 10–23 行，是**故意保留**的：`image_edit_op` 的 19 行承载了归一流量的
**1.69%**，`doc_summarize` 的 10 行承载 **1.36%**。它们是标准的单串命令 —— 紧致、真实，
只是行数少。不要为了让覆盖率数字好看而放松它们。

种子总覆盖率是行数的 5.1%。在这里没问题，**因为这份语料有真实的参照标签体系**：
`l1`/`l2` 逐行变化且覆盖 100%，所以 `k_locator: auto` 会拿它们（而不是覆盖 5.1% 的
措辞种子）去定位 K。此前每一份语料带的 `query_1st_category` 都只有一个常量值 ——
那是文件名，p1 会丢弃它。

## 5. 风险筛查，然后审计误报

助手是**生成**的，所以一行被错误处理会产出内容，而不是一个糟糕的结果页。共声明 8 个
类别。审计发现了两件事：

**长篇虚构 prompt 会触发所有关键词模式。** 虚构标记占语料行数的 2.0%，却占风险命中的
**15%** —— 7.5 倍富集，因为一条 500 字的角色扮演 prompt 词很多，而只要含一个就会命中。
`self_harm` 最极端：38% 的命中带虚构标记，其命中的**长度中位数是 565 字**，而语料整体
是 10 字。query 长度是这些清单最省事的第一道分诊筛子。

`financial_advice` 删掉了三个词，每个都有实测理由：`抄底` 命中了一段罗斯柴尔德人物设定；
`带单` 在 65,986 行中只命中 1 行，而那是宽**带单**独计费 —— 与 `finance_zh` 的 澳门
注记是同一个子串陷阱。留下的模式都要求一个**求建议的语框**。

**但 `self_harm` 仍然保持宽泛，这是本文件里唯一一处把权衡倒过来的地方。** 全部 16 条
命中都是第三人称 —— 虚构、历史（杜聿明）、新闻、一个卡通、一个抽象法律问题，**没有一条
是第一人称**。在这份语料上它是纯粹的误报制造机，而它被保留下来，因为漏报的代价是一个
正处于危机中的人拿到一段剧情梗概。

**有一行需要人来决定。** `minor_sexualisation` 命中一次：一名自述 15 岁的初中生询问自己
的身体尺寸 —— 而导出自带的类目体系把它归在 生活和情感/两性知识，一个没有任何未成年人
专门处理的通用性教育桶里。一个只命中一次的类别仍然值得声明；n=1 不能证明下一份导出里
没有。

## 6. 运行

```bash
python tools/prepare_assistant_corpus.py --head … --tail … -o data/raw/ai_assistant_pooled.parquet
.venv/bin/qmine models --config configs/live_ai_assistant.yaml --domain ai_assistant_zh
.venv/bin/qmine run --config configs/live_ai_assistant.yaml --domain ai_assistant_zh \
    --input data/raw/ai_assistant_pooled.parquet --run-id ai01 --smoke --offline   # 只验接线
.venv/bin/qmine run --config configs/live_ai_assistant.yaml --domain ai_assistant_zh \
    --input data/raw/ai_assistant_pooled.parquet --run-id ai01                     # 真跑
```

即使配置里已经写了输入路径，命令行上仍必须传 `--input` —— 新建运行没有它会拒绝启动。

跑完之后，把合并所换来的东西真正取出来：

```bash
python tools/vertical_crosstab.py runs/ai01/gen01 --weight-column weight
```

## 7. 无论运行结果怎么说，这份语料都支撑不了的结论

- **跨垂类的行数不含信息。** 导出对每个垂类每层固定抽取 1,000 行。某一类有 80% 落在
  一个垂类里，部分只是这个配额造成的。
- **无法推回总体**（§1.4）。这里的占比是层内、垂类内的；它们不能换算成「全量里有多少」。
- **相当一部分行是对话轮次，不是 query。**「他与皮肤不粘连，是独立个体」（医疗）、
  「目前没发现低于6.8的」（商品）、「前面讲的还记得吗」，脱离导出未携带的上下文就无法
  解读。它们是真实流量，也会被分析；但没有任何逐行方法能还原它们的意图，交付物应当
  如实称呼它们，而不是去猜。
- **参照标签恰恰在流量最大的地方最脏。** `👌 好的，继续吧` 被归在 33 个垂类中的 32 个；
  1.54% 的（垂类, query）对带有不止一个二级标签。
